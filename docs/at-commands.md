# 時刻関連の AT コマンド

出典: 3GPP TS 27.007、Fibocom L860 AT Commands User Manual §5.1 (+CCLK p.63-65、+CTZU p.65-66、+CTZR p.67-68)。
マニュアルは転載禁止のため、ここでは形式を要約しています。

## 送るコマンド

| コマンド | 用途 |
|---|---|
| `AT+CTZR=3` | タイムゾーン変更と UTC の通知 `+CTZEU` を有効にする。ltentp が起動時に毎回送る |
| `AT+CCLK?` | モデムの時計を読む。`--cclk-interval` 指定時に、秒の切り替わりを求めるため短い間隔で続けて送る |
| `AT+CTZU=1` | NITZ でモデムの時計を自動更新する (既定値。ltentp は変更しない) |

マニュアルによると、`AT+CTZR=3` はファームウェアのビルド設定によっては使えません。

## 応答の形式

| 行 | 形式 | ltentp での扱い |
|---|---|---|
| `+CTZEU: <tz>,<dst>[,<utime>]` | `<utime>` は UTC で `"YYYY/MM/DD,hh:mm:ss"` | UTC として chrony に送る |
| `+CTZE: <tz>,<dst>[,<time>]` | `<time>` は現地時刻 | 記録のみ (時刻は変換しない) |
| `+CTZV: <tz>` | タイムゾーンのみ | 記録のみ |
| `+CCLK: "<time>±zz"` | `<time>` は `yy/MM/dd,hh:mm:ss` の現地時刻 | 記録のみ。時刻欄からゾーンを引いて UTC にする。ゾーンがなければ UTC とみなす |

- `<tz>` は 15 分単位の整数で、範囲は −48〜+56 です。引用符付き (`"+36"`) と引用符なし (`+36`) のどちらも受け付けます
- `<dst>` は 0〜2 (夏時間の補正の時間数) です
- 時刻の中にカンマがあるので、フィールドは引用符の外のカンマだけで区切ります
- 年は 2 桁 (20yy とみなす) と 4 桁のどちらも受け付けます。マニュアルの `<utime>` の例は 4 桁、実機の `+CCLK` は 2 桁でした
- `<utime>` が省略された、または空の `+CTZEU` も受け付けます (chrony には送りません)

実機では `+CTZEU` がまだ一度も届いておらず、形式は確認できていません (下記)。解析に失敗した行も `PARSE_ERROR` として生の行を記録します。

## 実機で観測したこと (2026-11-17、Windows の MBIM AT トンネル経由)

| コマンド | 応答 |
|---|---|
| `AT+CGMR` | `18601.5001.00.01.17.30` |
| `AT+CTZR=?` | `+CTZR: (0-3)` (3 に対応) |
| `AT+CTZR?` | `+CTZR: 0` |
| `AT+CTZU?` | `+CTZU: 1` |
| `AT+CCLK?` | `+CCLK: "26/11/17,08:51:24+36"` (このときの PC の UTC は 08:51:24.5) |

`+CCLK` の時刻欄は JST (17:51) ではなく UTC と一致し、タイムゾーン欄は +36 (+9 時間) でした。TS 27.007 ではこの欄は現地時刻のはずです。
下の Linux での観測では現地時刻だったため、ltentp は TS 27.007 どおりに扱います。Windows で食い違った原因 (Windows が MBIM 経由でモデムの時計を設定した、など) は確認していません。

## 実機で観測したこと (2026-11-18、Debian 13 + iosm、IIJmio の SIM)

### 起動から登録まで

| 状態・操作 | 結果 |
|---|---|
| 起動直後 | `+CFUN: 4,0` (MBIM でも software radio off)、`+COPS: 2` (登録解除)、`+CTZR: 0`、`+CCLK: "70/01/01,01:03:22+00"` |
| `AT+CPIN?` | `CFUN=4` では `ERROR`、`CFUN=1` では `+CPIN: READY` |
| FCC unlock 前の `AT+CFUN=1` | `OK` を返すが `+CFUN: 4` のまま |
| FCC unlock | ModemManager 上流の `data/dispatcher-fcc-unlock/8086:7560` の Lenovo 方式 (`AT+GTFCCLOCKGEN`/`VER`/`MODEUNLOCK`、SMBIOS type 133 から求めたハッシュ) で成功 |
| unlock 後の `AT+CFUN=1` | `+CFUN: 1,0` になるが、`+COPS: 2` のままで網を探さない |
| `AT+COPS=0` | 約 1 秒で `+COPS: 0,0,"KDDI",7` (LTE)、`+CEREG: 0,1` |

これらは再起動のたびに必要です。ltentp は `AT+CFUN`・`AT+COPS` を送らないので、外で済ませておきます。

### AT ポート

- `/dev/wwan0at0`・`/dev/wwan0at1` とも応答します。Windows の AT トンネルで起きた「最初の応答が返らない」問題は起きません
- 1 つのポートを複数のプロセスで同時に開けます。応答はどれか 1 つの読み手にしか渡らないので、ltentp が使うポートで別のプロセスから AT を送ってはいけません
- `AT+CEREG=2` の URC は at0 と at1 の両方に同時に届きました。URC は `AT+CTZR` などを設定したポートに限らず届くようです

### 時刻

- **`+CTZEU` は届きませんでした。** 両方のポートで `AT+CTZR=3` を設定した状態で、モデムの時計が `70/01/01 +00` から網時刻 `+36` に変わった最初の登録でも (再起動して 2 回確認)、その後 1 時間の間も、登録をやり直したときも出ていません。`+CEREG` の URC は同じポートに届いているので、URC が落ちているわけではありません
- `+CCLK` は登録の直後に網時刻になりました。時刻欄は現地時刻 (`26/11/18,10:10:19+36` のとき UTC は 01:10:19) です
- `AT+CCLK?` の応答時間は 1.6〜5.8 ms (10 ms 間隔で続けて送ったときの中央値 4.5 ms)
- 秒の切り替わりは ±6〜8 ms の幅で求まり、同じ設定のままなら 1 秒ごとの値のばらつき (標準偏差) は約 3 ms です
- 秒の切り替わりのずれ (モデム − システム) は、時点によって大きく違いました。仕組みは分かっていません:

  | 時点 | ずれ |
  |---|---|
  | 1 回目の起動。最初の登録 (10:09) から約 65 分、登録のやり直し (10:15) から約 60 分後 | +10.5 ms (60 回の平均) |
  | 再起動直後、網の時刻が入る前 (時計は 1970 年から) | −0.5614 s 相当の位置 (66 回) |
  | 最初の登録 (11:43:27) で網時刻になってから 3 分以内 | −0.5618 s (位置は変わらず、秒の数だけ変わった) |
  | `CFUN=4` → `CFUN=1` と `COPS=0` で登録し直した (11:47:40) 後 | −0.817 s (位置が変わり、少なくとも 8 分間 ±3 ms で一定) |

  登録の直後は 1 秒近くずれていて、網時刻は秒単位でしか入っていないように見えます。一方、1 回目の +10.5 ms は登録から約 1 時間後の値で、時間がたつと 1 秒より細かく合わせ直される可能性は残っています (未検証。登録から 1 時間以上の記録で確かめる)
- `AT+XSIB16INFO` (`=?` は `(0,1)`) と `AT+XSIB8INFO` がファームウェアのコマンド一覧 (`AT+CLAC`) にありますが、マニュアルにはありません。`=1` にして最初の登録を待っても通知は来ませんでした。`?` は `+CME ERROR: not found` です
- 登録の操作中に別の AT を同じポートに送ると、実行中のコマンドは中断されます (`AT+COPS=0` が 60 秒返らなかったとき、次の `AT+CCLK?` で `+CME ERROR: Command aborted by user`)。時間のかかる操作は ltentp と別のポートで送ります
- 再起動直後は `CFUN=1` にしても SIM がしばらく `SIM NOT INSERTED` / `not-initialized` のことがありました。数十秒後に準備ができ、自動で登録しました
- `AT+XNITZINFO` は `operation not supported` です
- MBIM の `mbimcli --ms-query-nitz` は `+CCLK` と同じ現地時刻と `Time zone offset minutes: 540` を返します

## Linux での AT ポート

- `iosm` ドライバは 7560 に対して `/dev/wwan0at0`・`/dev/wwan0at1` (AT)、`/dev/wwan0mbim0` (MBIM)、ネットワークインターフェース `wwan0` を作ります
- AT ポートは TTY ではなく WWAN の文字デバイスです
- AT 経路には割り込みのまとめがかかりません (`IRQ_ACC_BACKOFF_OFF`)。データ経路は約 1 ms まとめられます (`IRQ_ACC_BACKOFF_MUX`)
- ModemManager は AT ポートを使うため、ltentp 用に 1 本外す必要があります (`contrib/udev/`)。実機では ModemManager を入れずに使っています
