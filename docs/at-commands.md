# 時刻関連の AT コマンド

出典: 3GPP TS 27.007、Fibocom L860 AT Commands User Manual §5.1 (+CCLK p.63-65、+CTZU p.65-66、+CTZR p.67-68)。
マニュアルは転載禁止のため、ここでは形式を要約しています。

## 送るコマンド

| コマンド | 用途 |
|---|---|
| `AT+CTZR=3` | タイムゾーン変更と UTC の通知 `+CTZEU` を有効にする。ltentp が起動時に毎回送る |
| `AT+CCLK?` | モデムの時計を読む。`--cclk-interval` 指定時に定期的に送る |
| `AT+CTZU=1` | NITZ でモデムの時計を自動更新する (既定値。ltentp は変更しない) |

マニュアルによると、`AT+CTZR=3` はファームウェアのビルド設定によっては使えません。

## 応答の形式

| 行 | 形式 | ltentp での扱い |
|---|---|---|
| `+CTZEU: <tz>,<dst>[,<utime>]` | `<utime>` は UTC で `"YYYY/MM/DD,hh:mm:ss"` | UTC として chrony に送る |
| `+CTZE: <tz>,<dst>[,<time>]` | `<time>` は現地時刻 | 記録のみ (時刻は変換しない) |
| `+CTZV: <tz>` | タイムゾーンのみ | 記録のみ |
| `+CCLK: "<time>±zz"` | `<time>` は `yy/MM/dd,hh:mm:ss` | 記録のみ。時刻欄は UTC として解釈し、ゾーンは適用しない |

- `<tz>` は 15 分単位の整数で、範囲は −48〜+56 です。引用符付き (`"+36"`) と引用符なし (`+36`) のどちらも受け付けます
- `<dst>` は 0〜2 (夏時間の補正の時間数) です
- 時刻の中にカンマがあるので、フィールドは引用符の外のカンマだけで区切ります
- 年は 2 桁 (20yy とみなす) と 4 桁のどちらも受け付けます。マニュアルの `<utime>` の例は 4 桁、実機の `+CCLK` は 2 桁でした
- `<utime>` が省略された、または空の `+CTZEU` も受け付けます (chrony には送りません)

実機の `+CTZEU` の形式はまだ確認していません。解析に失敗した行も `PARSE_ERROR` として生の行を記録します。

## 実機で観測したこと (2026-11-17、Windows の MBIM AT トンネル経由)

| コマンド | 応答 |
|---|---|
| `AT+CGMR` | `18601.5001.00.01.17.30` |
| `AT+CTZR=?` | `+CTZR: (0-3)` (3 に対応) |
| `AT+CTZR?` | `+CTZR: 0` |
| `AT+CTZU?` | `+CTZU: 1` |
| `AT+CCLK?` | `+CCLK: "26/11/17,08:51:24+36"` (このときの PC の UTC は 08:51:24.5) |

`+CCLK` の時刻欄は JST (17:51) ではなく UTC と一致し、タイムゾーン欄は +36 (+9 時間) でした。TS 27.007 ではこの欄は現地時刻のはずなので、ファームウェアの癖なのか、NITZ の受け方によるのかは不明です。
`+CTZEU` の値と比べて確定させるまで、`CCLK` は chrony に送りません。

## Linux での AT ポート

- `iosm` ドライバは 7560 に対して `/dev/wwan0at0`・`/dev/wwan0at1` (AT)、`/dev/wwan0mbim0` (MBIM)、ネットワークインターフェース `wwan0` を作ります
- AT ポートは TTY ではなく WWAN の文字デバイスです
- AT 経路には割り込みのまとめがかかりません (`IRQ_ACC_BACKOFF_OFF`)。データ経路は約 1 ms まとめられます (`IRQ_ACC_BACKOFF_MUX`)
- ModemManager は AT ポートを使うため、ltentp 用に 1 本外す必要があります (`contrib/udev/`)。通知が `AT+CTZR=3` を送ったポートにだけ届くのかは未確認です
